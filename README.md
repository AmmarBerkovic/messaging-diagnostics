# Messaging Diagnostics Assistant

A Go command-line tool that answers plain-English questions about SMS and email delivery problems,
such as "Why are UK SMS failing since yesterday?" or "What happened to message msg_d0f06d?".

It uses Gemini **function calling**. The model is given a few tools, decides which ones to call, the Go
code runs them against a local log database, and the model writes a diagnosis that cites log entries
and error-code documentation. Every tool call is printed so the reasoning is visible.

> **All data in this project is synthetic.** The delivery logs are generated by `diag seed` from a fixed
> random seed. Organisations are invented, phone numbers come from ranges reserved for fiction
> (UK 07700 900xxx, North American 555-01xx) and email domains use the reserved `.example` TLD.
> No real company, customer or message data is used anywhere.

## How it works

```
question ──► Agent ──► Gemini (tools: search_logs, get_message, lookup_error_code, report_diagnosis)
               ▲            │
               │            ▼ function calls
               └── results ◄── Go executes tool against SQLite / knowledge base
```

The agent loop in `internal/agent` is the core of the project:

1. Start a session with a system prompt (which includes the dataset's "current time") and the tool
   declarations.
2. Send the question. If the model replies with function calls, run each one and send the results back.
3. Repeat until the model calls `report_diagnosis`, which carries the final answer as structured
   arguments, including a `root_cause_category` chosen from a fixed enum.
4. Stop with an error after `--max-steps` turns (default 8) so a confused model cannot loop forever
   or burn through the free quota.

Tool errors (a bad timestamp, an unknown code) are returned to the model as `{"error": ...}` results
instead of aborting, so it can correct itself on the next turn.

### Tools

| Tool | What it does |
|---|---|
| `search_logs` | Filters by channel, provider, country, org, sender, status, error code, recipient domain and time range. Returns **aggregates**: totals, failure rate, breakdowns by status, error code, sender, country, org, domain and hour, plus at most 5 sample failed messages. |
| `get_message` | Returns one full record by message id. |
| `lookup_error_code` | Explains a provider error code (about 25 Twilio, Telnyx and SMTP codes) with a link to the official documentation. |
| `report_diagnosis` | Not a data tool: the model calls it to finish, which gives us structured output. |

Tools never return the raw log. Aggregates keep each request small, which matters on free-tier token
limits, and they are what an engineer would look at first anyway.

### Packages

| Package | Responsibility |
|---|---|
| `cmd/diag` | CLI: `seed`, `ask`, `eval` subcommands and output formatting. |
| `internal/llm` | The `Model` and `Session` interfaces plus vendor-neutral tool types. |
| `internal/llm/llmtest` | A scripted fake model used by the tests. |
| `internal/gemini` | Adapter from `llm.Model` to the official `google.golang.org/genai` SDK. The only package that imports it. |
| `internal/agent` | The tool-calling loop, step limit and structured diagnosis. |
| `internal/tools` | Tool declarations and implementations. |
| `internal/store` | SQLite schema, inserts and aggregate queries. |
| `internal/seed` | Deterministic synthetic traffic and planted incidents with known root causes. |
| `internal/kb` | Error-code knowledge base and the list of root cause categories. |
| `internal/eval` | Runs one question per planted incident and scores the answers. |

## Planted incidents

`diag seed` writes about 4,100 messages over 72 hours: normal traffic with a few percent of background
failures, plus six incidents. Each incident's root cause is stored in the database for the eval.

| Incident | Root cause category |
|---|---|
| UK SMS from one sender filtered by carriers since 14:00 yesterday (Twilio 30007) | `carrier_filtering` |
| Six recipients who replied STOP keep being messaged (Twilio 21610) | `opt_out` |
| A campaign sent to a bad contact list: invalid numbers and landlines (Telnyx 40310, 40001) | `invalid_number` |
| A 20-minute burst rejected by the provider's API rate limit (Telnyx 10011) | `rate_limited` |
| One recipient domain stopped accepting mail, so one org's email hard-bounces (SMTP 550 5.1.2) | `recipient_domain_failure` |
| One org's provider credentials expired, so all its SMS are rejected (Twilio 20003) | `auth_failure` |

## Getting started on Windows

You need Go 1.24 or later. No C compiler is needed: SQLite runs through a pure-Go driver.

### 1. Get a free Gemini API key

1. Go to [aistudio.google.com](https://aistudio.google.com) and sign in with a Google account.
2. Open **Get API key** (or go straight to [aistudio.google.com/apikey](https://aistudio.google.com/apikey))
   and create a key. No billing account is needed for the free tier.
3. Keep the key out of the repository. It is read from the `GEMINI_API_KEY` environment variable only.

Free-tier limits are set per Google Cloud project and per model, and Google shows the current numbers
on the [AI Studio rate limit page](https://aistudio.google.com/rate-limit) rather than in a fixed table.
Free-tier prompts may be used by Google to improve its products, which is fine here because all data
is synthetic.

### 2. Build and seed

PowerShell:

```powershell
cd messaging-diagnostics
go build -o diag.exe ./cmd/diag
.\diag.exe seed
```

### 3. Ask a question

```powershell
$env:GEMINI_API_KEY = "your-key-here"     # this terminal session only
.\diag.exe ask "Why are UK SMS failing since yesterday?"
.\diag.exe ask "Why has org_evergreen's email bounce rate jumped?"
```

Git Bash:

```bash
export GEMINI_API_KEY=your-key-here
./diag.exe ask "Every SMS from org_foxglove has failed for the last few hours. Why?"
```

### 4. Run the eval

```powershell
.\diag.exe eval
```

This asks one question per planted incident and checks whether the reported `root_cause_category`
matches the ground truth, then prints a score such as `Score: 5/6 (83%)`. It waits 15 seconds between
questions to stay inside free-tier requests-per-minute limits (`--delay` changes this), and rate-limited
requests are retried with exponential backoff.

### Options

| Flag / variable | Default | Purpose |
|---|---|---|
| `--model` / `GEMINI_MODEL` | `gemini-3.8-flash` | Any Gemini model with function calling, e.g. `gemini-3.5-flash-lite` for higher free limits. |
| `--db` / `DIAG_DB` | `diag.db` | SQLite file (gitignored). |
| `--max-steps` | `8` | Model turns allowed per question. |
| `seed --seed` | `42` | Random seed. The same seed and `--now` always produce identical data. |
| `seed --now` | current hour | The dataset's "current time", so "since yesterday" stays meaningful. |

## Tests

```bash
go vet ./...
go test ./...
```

Neither needs a network connection or an API key. The agent and eval tests use a scripted fake model
(`internal/llm/llmtest`) that issues tool calls, and the tool tests run against a seeded in-memory
SQLite database. Covered: every tool, that each planted incident is visible through `search_logs`, the
agent loop end to end, the step limit, recovery from a malformed report, eval scoring, and the Gemini
request and response conversion.

## Design notes

* **The model sits behind a two-method interface** (`StartSession`, `Send`). Tests swap in a fake, and
  replacing Gemini with another provider means writing one adapter package.
* **The session owns the conversation history.** The Gemini adapter uses the SDK's chat, which replays
  the model's own turns verbatim, including the thought signatures Gemini requires across function
  calling turns. The agent never handles provider-specific data.
* **Structured output through a tool.** Asking for the final answer as `report_diagnosis` arguments
  gives a schema-checked enum for scoring, without parsing free text.
* **`modernc.org/sqlite`** is a pure-Go SQLite, so `go build` works on Windows without cgo or a C
  toolchain.
* **Timestamps are stored as fixed-width UTC strings**, which sort in time order, so time filters are
  string comparisons and hourly buckets are `substr(ts, 1, 13)`.

## Limitations

* The eval only checks the root cause category, not the quality of the explanation.
* `search_logs` returns fixed breakdowns; it cannot, for example, group by template.
* The knowledge base is a curated list of about 25 codes, not the providers' full catalogues.
